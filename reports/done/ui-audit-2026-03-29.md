# UI Audit Report — Playas de Murcia

## Date: 2026-03-29

## Executive Summary

Playas de Murcia is a functional, well-structured coastal tourism site with a solid technical foundation (clean component architecture, proper accessibility attributes, consistent token usage). However, when measured against CSS Design Award-caliber references (Hautes-Alpes, BLESS Collection, Cascioni, Grand Hotel Central, Omai Villas), the site falls into the category of "clean informational portal" rather than "aspirational travel destination." The gap is not about broken things — it is about missing emotional resonance, typographic sophistication, and the generous breathing room that makes award-winning travel sites feel like an experience rather than a directory.

The three largest systemic gaps are: (1) **single sans-serif typography** — every reference site pairs a serif display face with a sans-serif body; Playas de Murcia uses Inter for everything, which flattens the hierarchy and makes headings feel utilitarian rather than evocative; (2) **insufficient whitespace** — section padding tops out at `py-16`/`py-20` (64-80px) where references use 7-9rem (112-144px), and cards/grids are tightly packed; (3) **data display styling** — the weather widget, practical info card, services grid, and beach status widget all read like admin dashboards with dense rows of small text, not like the polished, editorial data presentations seen on luxury travel sites.

**Top 5 priorities:**

1. Introduce a serif display typeface for headings site-wide (highest visual impact, lowest code effort)
2. Redesign the weather widget and practical info card on beach detail into editorial, card-based layouts
3. Increase vertical section padding globally to 6-9rem and card gaps to 1.5-2rem
4. Add hero imagery to inner pages (collections, municipalities) instead of flat gradient backgrounds
5. Refine the BeachCard to include richer content hierarchy and more generous internal spacing

## Page-by-Page Analysis

### 1. Homepage

**Source:** `src/routes/index.tsx`

#### Critical

- **C1 — Sans-serif-only headings kill the travel mood.** The `h1` at line 91 uses `font-extrabold` Inter at `text-4xl`/`text-5xl`/`text-6xl`. Every reference site uses a serif or display serif at light-to-regular weight for the hero headline. Inter extrabold reads as SaaS landing page, not Mediterranean coastline. The tagline "Donde el Mediterraneo abraza la costa" is poetic copy trapped in a utilitarian typeface.
  - **Fix:** Load a serif display face (candidates: Playfair Display, Cormorant Garamond, DM Serif Display) at weights 300-500. Apply to all `h1` and `h2` elements. Change hero `h1` to `font-light` or `font-normal` at `text-6xl`/`text-7xl`/`text-8xl`. Reference: Cascioni uses Conso Serif at ultra-light; BLESS uses Bodoni 72; Grand Hotel Central uses Joane light-100.

- **C2 — Hero gradient overlay is top-heavy and too opaque.** Line 86: `from-ocean-900/70 via-ocean-900/75 to-ocean-900/90` — this applies the heaviest opacity at the bottom (90%) but is already 70% at the top. Reference sites use overlays focused on the bottom third only, letting the sky/landscape breathe. The current gradient makes the entire hero feel like a dark card rather than an immersive window.
  - **Fix:** Change to `from-transparent via-ocean-900/20 to-ocean-900/80`. Let the top 40% of the image show through clearly.

#### Important

- **I1 — Section padding is 30-50% below reference standard.** Featured beaches section (line 134) uses `py-16 sm:py-20 lg:py-24` (64/80/96px). Grand Hotel Central uses 7.8rem (125px) section padding. Omai Villas uses even more.
  - **Fix:** Increase to `py-20 sm:py-28 lg:py-36` (80/112/144px) for major sections.

- **I2 — Municipality section is a flat list of small cards with no imagery.** Lines 208-229: each municipality is a text-only card with a number badge. Reference sites would show a stunning photo per municipality with text overlay. The current 5-column grid makes each card tiny and compressed.
  - **Fix:** Reduce to 2-3 columns. Add a background image per municipality (even if using a representative beach photo). Overlay the name and count on the bottom. Minimum card height: 200px.

- **I3 — "Region highlights" section (lines 247-331) feels like generic marketing.** Three text blocks with small icons. No photography, no editorial depth. On reference sites, this kind of content would be a full-width editorial strip with a large background image and overlaid text.
  - **Fix:** Either make this a full-bleed editorial section with a large coastal photo and overlaid text blocks, or remove it. The current implementation adds little visual value.

- **I4 — Featured beaches grid gap is too tight.** Line 153: `gap-x-4 gap-y-6` (16/24px). At CSS Design Award level, card grids use 24-32px gaps.
  - **Fix:** Change to `gap-6 xl:gap-8` (24/32px).

#### Refinement

- **R1 — CTA buttons are fine but could be more restrained.** The "Explorar todas las playas" button (line 102) is appropriate, but the secondary "Ver colecciones" button border at `border-white/20` is nearly invisible.
  - **Fix:** Increase to `border-white/30`.

- **R2 — Section header pattern is repetitive.** Every section uses the same `text-ocean-600 uppercase tracking-wider` label + `text-3xl font-bold` heading. This works but becomes monotonous.
  - **Fix:** Vary the pattern: some sections could use just the heading, others could use a different label treatment.

#### What Works Well

- Hero copy is genuinely evocative — "Donde el Mediterraneo abraza la costa" is excellent.
- Staggered animation on hero elements (`[animation-delay:75ms]`, `[animation-delay:150ms]`) is well-executed.
- Scroll reveal animations use appropriate cubic-bezier easing (`0.16, 1, 0.3, 1`) per styles.css.
- The two-button hero CTA pattern (primary + ghost) follows reference patterns.
- Card hover effects (`motion-safe:hover:-translate-y-1` + `hover:shadow-lg`) are polished and respect reduced-motion.

### 2. Beach Detail

**Source:** `src/routes/playas/$slug.tsx`

**Note:** Screenshots show "Not Found" because the URL lacked a valid slug. Analysis is based on source code inspection.

#### Critical

- **C3 — Weather widget looks like a developer debug panel, not a tourism feature.** (`src/components/weather-widget.tsx`) The TodayCard (lines 186-236) crams the sky description, temperature, wind speed+direction, and UV index into a single dense row with `text-sm` and `text-xs` sizing. The forecast grid (lines 260-298) uses `grid-cols-2 sm:grid-cols-3` of tiny cards with `text-xs` and even `text-[10px]` wind data. The UV badge (line 228) is a colored rectangle jammed inline.
  - **Why it looks unprofessional:**
    - Too much data crammed into too little space
    - No visual hierarchy — temperature, wind, and UV are given equal visual weight
    - `text-[10px]` (line 276) is below minimum readable size for body text
    - The forecast day cards (line 262) have `bg-gray-50/60 border border-gray-100` — the faintest possible styling, making them look like placeholder UI
    - No visual delight — no gradient backgrounds, no thoughtful color, no subtle illustrations
  - **Fix — complete redesign:**
    1. Today section: make temperature the hero number at `text-4xl font-light`, sky icon at 48px, sky description below at `text-base`. Wind and UV go in a secondary row with more spacing.
    2. Forecast: use a horizontal scroll strip (not grid) with each day as a `min-w-[4.5rem]` column. Remove the `text-[10px]` wind data from forecast cards — it adds clutter with no user value.
    3. Add a subtle blue gradient background (`from-sky-50 to-ocean-50`) to the entire widget instead of plain white.
    4. Use `text-xs` as the absolute minimum font size, never `text-[10px]`.
    5. Reference: Sanguli Salou's weather integration uses a single temperature number + icon, clean and large.

- **C4 — Practical Info Card is a key-value dump.** (`src/components/practical-info-card.tsx`) Lines 87-98: `InfoRow` renders each piece of data as `dt/dd` with `border-b border-gray-100 py-3`. This creates a long vertical list of thin gray lines that looks like a settings panel or admin form. Up to 10 rows (length, soil, waves, orientation, access difficulty, occupancy, child-safe, shade, water quality, season) stacked sequentially.
  - **Fix:**
    1. Group related items: Physical characteristics (length, soil, orientation) | Conditions (waves, occupancy, water quality) | Family info (child-safe, shade, access) | Best season
    2. Use a 2-column grid for the groups instead of a single-column list
    3. Replace the `border-b` separator lines with card-based groupings
    4. Make the badge-styled values (occupancy, access difficulty, water quality) more visually prominent — they are currently tiny `text-xs` pills lost in the row

- **C5 — Sidebar data density is overwhelming.** Line 246 stacks WeatherWidget + BeachStatusWidget + PracticalInfoCard + ContactInfo in a single `space-y-6` column. On a beach with full data, this creates 4 back-to-back white cards with 40+ data points visible without scrolling. Reference sites show 1-2 key data points prominently and hide details behind expandable sections or tabs.
  - **Fix:** Consider collapsing PracticalInfoCard into an expandable accordion that shows 3-4 key facts by default. Move ContactInfo into the main content area near the map.

#### Important

- **I5 — BeachStatusWidget uses a different visual language than WeatherWidget.** The status widget (line 179) uses `border-ocean-100 bg-ocean-50/40` (tinted background with colored border), while the weather widget uses `border-gray-200/60 bg-white` (plain white). These are adjacent sidebar cards that should share a consistent surface treatment.
  - **Fix:** Standardize both to the same card style. If using a tinted background for status (to convey "live data"), apply a similar tint to the weather widget.

- **I6 — Services and Activities grids are identical in styling.** (`src/components/services-grid.tsx` and `src/components/activities-grid.tsx`) Both use `grid-cols-2 sm:grid-cols-3 lg:grid-cols-4` with identical card styling. When both sections appear on a beach page, they are visually indistinguishable — the user cannot tell at a glance whether they are looking at services or activities.
  - **Fix:** Differentiate with subtle color. Services could use `bg-ocean-50` tinted items; activities could use `bg-amber-50` or `bg-emerald-50` tinted items. Or use a different icon treatment (services in circles, activities in squares).

- **I7 — Hero image section is short.** Line 156: `h-64 sm:h-80 lg:h-96` (256/320/384px). For a beach detail page, the hero image should be immersive. Reference sites use 50-70vh for detail page heroes.
  - **Fix:** Change to `h-72 sm:h-96 lg:h-[32rem]` minimum, or use `min-h-[50vh]`.

- **I8 — Gallery section has no lightbox.** Lines 329-422: `BeachGallery` renders a grid/scroll of images with no way to view them full-screen. Users expect to tap/click beach photos to see them larger.
  - **Fix:** Add a lightbox interaction (even a simple one using native `<dialog>`).

#### Refinement

- **R3 — "Sobre esta playa" heading is generic.** Line 239: "Sobre esta playa" is functional but not evocative. Consider removing the heading entirely and letting the description paragraph speak for itself, or using the beach name.

- **R4 — The "Fuente: AEMET" / "Fuente: Open-Meteo" attribution.** (weather-widget.tsx line 417) This is good for transparency but `text-xs text-gray-400` right-aligned looks like debug info. Make it a subtle footer line within the card.

- **R5 — CertificationsBadge placement.** (line 228) Certifications appear between the breadcrumb and the main content grid, isolated. They would have more impact inside the hero overlay or integrated into the description card.

#### What Works Well

- The 3-column layout (2-col main + 1-col sidebar) at line 236 is the right structural choice for a detail page.
- `lg:sticky lg:top-20 lg:self-start` on the sidebar (line 246) keeps data visible during scroll — good UX.
- Breadcrumb placement and depth is correct per guidelines.
- The NearbyCarousel provides good cross-linking.

### 3. Explorer

**Source:** `src/routes/explorar/index.tsx`

#### Critical

- **C6 — The page hero is a flat gradient with no imagery.** Lines 279-289 use `PageHero` which renders `bg-linear-to-br from-ocean-900 via-ocean-800 to-ocean-700` (page-hero.tsx). Every reference site uses photography in page headers. The flat teal gradient is the single most "template website" element on the site.
  - **Fix:** Add a blurred/dimmed coastal photograph as a background to `PageHero`, with the gradient overlay for text readability. Even a single reusable photo is better than a flat gradient.

#### Important

- **I9 — Filter sidebar + results layout gap.** Line 296: `flex gap-10` (40px) between sidebar and results. This is reasonable but the sidebar has no visual separation from the results area — no border, no background difference, no distinct surface.
  - **Fix:** Give the filter sidebar a subtle background (`bg-white rounded-2xl p-5 shadow-sm`) or a left border to visually separate it from results.

- **I10 — BeachCard content area is sparse.** The card (beach-card.tsx lines 107-112) shows only `h3` (beach name) and `p` (municipality). No description snippet, no key characteristics. Reference sites show 1-2 lines of description or key attributes (beach type, length) in listing cards.
  - **Fix:** Add a truncated description line or 2-3 key attributes (soil type, length, rating) below the municipality name. Use `text-sm text-gray-500 line-clamp-2`.

- **I11 — Weather badge on cards is small and easy to miss.** (beach-card.tsx line 75) `bg-white/80 px-2 py-0.5 text-xs` — a tiny translucent pill in the top-left corner of the image. The temperature is useful data but the presentation is too subtle.
  - **Fix:** Increase to `px-2.5 py-1 text-sm` and use a slightly more opaque background `bg-white/90`.

#### Refinement

- **R6 — Search bar in hero is narrow.** Line 287: `max-w-lg` (32rem = 512px). For a search-centric page, this could be wider.
  - **Fix:** `max-w-xl` or `max-w-2xl` on desktop.

- **R7 — Pagination is present but no "results per page" indicator.** The `PageInfo` component shows pagination metadata, but there is no way for users to change the page size (15 items per page, line 117).
  - **Fix:** Low priority, but consider adding a simple selector.

#### What Works Well

- Active filter chips with individual remove buttons (lines 334-367) are well-designed.
- The `FilterToggleButton` for mobile (line 317) with active count badge is good UX.
- Sort select integration is clean.
- Empty state with action button follows the guidelines perfectly.

#### Important

- **R9 — "Ver coleccion" vs "Explorar" link text.** Sea cards say "Explorar" (line 215) while thematic cards say "Ver coleccion" (line 150). Pick one verb consistently.

### 5. Municipalities

**Source:** `src/routes/municipios/index.tsx`

#### Critical

- **C8 — No imagery whatsoever on this page.** This is the page most damaged by the absence of photography. Municipalities are places with distinct visual identities — Cartagena's Roman ruins, Aguilas' dramatic cliffs, La Manga's narrow strip. Showing them as text-only cards with service pills is a serious undersell.
  - **Fix:** Add a hero photograph per municipality. Each card should have an image at top (like BeachCard) or be a full-image card with overlay text.

#### Important

- **I15 — Service pills on municipality cards feel like admin metadata.** Lines 122-137: small `text-xs` pills showing services like "Hamacas," "Parking," "Duchas." This reads like a database query result, not travel inspiration. Users don't choose municipalities based on whether beaches there have parking.
  - **Fix:** Replace service pills with 1-2 sentences of evocative description, or show the top 2-3 beach names instead. Keep services for the beach detail page.

- **I16 — Card layout is monotonous.** 9 identical white cards in `grid-cols-1 sm:grid-cols-2 xl:grid-cols-3`. All the same height, same structure, same visual weight. Cartagena (69 beaches) looks identical to La Union (2 beaches).
  - **Fix:** Feature the top 3-4 municipalities as larger cards (2-col span, with image) and show smaller ones in a more compact format. Size should correlate with importance/beach count.

#### Refinement

- **R10 — Blue flag count as a card-level metric.** Lines 113-119: showing blue flag count per municipality is informative but adds visual noise alongside the beach count. Consider removing from the card and showing only on the municipality detail page.

#### What Works Well

- The `computeMunicipalityStats` function (lines 19-52) is well-structured for data aggregation.
- The page subtitle "9 municipios con 194 playas en la Region de Murcia" is informative.

## Cross-Cutting Issues

### XC1 — No serif typeface anywhere on the site

**Impact:** High | **Pages:** All | **Effort:** Low

Every single heading on every page uses Inter (sans-serif) at `font-extrabold` or `font-bold`. This is the single most impactful difference between this site and the references. All six reference sites use serif faces for display typography.

**Fix:** Add a serif font via Google Fonts in `src/routes/__root.tsx` line 169. Candidates:

- `DM Serif Display` (free, Google Fonts, similar to Bodoni)
- `Cormorant Garamond` (elegant, supports Spanish characters)
- `Playfair Display` (versatile, works at large and medium sizes)

Apply via a CSS custom property like `--font-display` and use it for `h1`, `h2`, and hero text. Keep Inter for body, UI, and small text.

### XC2 — Inner page heroes are identical flat gradients

**Impact:** High | **Pages:** Explorer, Collections, Municipalities | **Effort:** Medium

`src/components/page-hero.tsx` renders the same `bg-linear-to-br from-ocean-900 via-ocean-800 to-ocean-700` gradient with a single blurred decorative circle on every inner page. This makes all pages feel interchangeable.

**Fix:** Extend `PageHero` to accept an optional `backgroundImage` prop. Each page provides a relevant photo. The gradient overlay ensures text readability.

### XC3 — Vertical spacing is 30-50% below reference standard

**Impact:** Medium | **Pages:** All | **Effort:** Low

Current section padding: `py-16` (64px) / `py-20` (80px). Reference standard: `py-24` (96px) to `py-36` (144px). Current card gaps: `gap-5`/`gap-6` (20/24px). Reference standard: `gap-6`/`gap-8` (24/32px).

**Fix:** Global search-and-replace:

- Section padding: `py-16 sm:py-20` -> `py-20 sm:py-28 lg:py-32`
- Card grid gaps: `gap-5` -> `gap-6`, `gap-6` -> `gap-8`

### XC4 — `font-extrabold` (800) is overused

**Impact:** Medium | **Pages:** All | **Effort:** Low

All `h1` elements use `font-extrabold`. This is the heaviest weight in the Inter range. Reference sites use light-to-medium weights for headings (100-400), creating elegance rather than impact. The extrabold weight makes headings feel heavy and corporate.

**Fix:** With the serif typeface, use `font-normal` or `font-light` for `h1` elements. For `h2` elements, use `font-semibold` (600) instead of `font-bold` (700). Reserve `font-bold` and above for small-text emphasis (badges, stats).

### XC5 — No transition/animation on page navigation

**Impact:** Low | **Pages:** All | **Effort:** Medium

Page transitions are instantaneous. Reference sites (BLESS, Grand Hotel Central) use 0.3-0.6s fade/slide transitions between pages.

**Fix:** Consider adding a simple opacity fade transition using TanStack Router's navigation events. Lower priority than other items.

### XC6 — Footer is dense and utilitarian

**Impact:** Low | **Pages:** All | **Effort:** Medium

`src/components/site-footer.tsx` is a functional 3-column grid of links. Reference sites use the footer as an editorial element with generous spacing, a background image, or a newsletter signup.

**Fix:** Increase footer padding from `py-12` (48px) to `py-16` (64px). Add more vertical spacing between sections. Consider adding a subtle background texture or a wave illustration.

## Shared Components Audit

### Navigation

**Source:** `src/routes/__root.tsx`, lines 363-464

**Strengths:** Sticky nav with backdrop blur on scroll, popover dropdown with hover trigger, mobile hamburger with accordion, active state indicators with bottom border.

**Issues:**

- The nav uses `bg-nav` (solid) on mobile and `bg-nav/95 backdrop-blur-md` on desktop. The difference is subtle but could cause visual inconsistency during transitions.
- No logo/icon — just the text "Playas de Murcia" in `text-base font-bold`. Reference sites all have a distinctive logo mark. Even a simple wave icon would add brand presence.
- The "Descubrir" dropdown (line 394) is the only dropdown item. Its label is vague — "Descubrir" what? Consider renaming to "Explorar" or removing the dropdown in favor of direct links.

### Footer

**Source:** `src/components/site-footer.tsx`

**Strengths:** Clean 3-column layout, municipality links with beach counts, proper dark theme.

**Issues:**

- Beach count badges (`text-[10px]`, line 57) are extremely small. Minimum should be `text-xs`.
- No branding beyond text. Consider adding a tagline or subtle illustration.
- "Datos del Ministerio de Transicion Ecologica" (line 107) — good for attribution but the accent is missing: should be "Transicion Ecologica" -> "Transicion Ecologica" (the source string already has the right text, just confirming).

### BeachCard

**Source:** `src/components/beach-card.tsx`

**Strengths:** Clean card structure, proper image handling with ResponsiveImage, weather badge, occupancy badge, tag pills, hover effects with reduced-motion support.

**Issues:**

- Content area (lines 107-112) is too sparse: only beach name + municipality. No description, no key attributes. This makes the explorer grid look like a photo gallery with captions rather than informative cards.
- The `aspect-[4/3]` image ratio (line 64) is appropriate but makes cards tall. Consider `aspect-[3/2]` for a more cinematic feel that matches reference sites.
- Internal padding `p-5` (20px) is adequate but `p-6` (24px) would give more breathing room.
- The gradient overlay `from-black/30 to-transparent` (line 73) is very subtle. Tags at the bottom of the image may have contrast issues on light-colored beach photos.

### PageHero

**Source:** `src/components/page-hero.tsx`

**Strengths:** Consistent structure, gradient background, centered content.

**Issues:**

- The decorative blur circle (lines 11-13) at `opacity-10` is barely visible and adds no visual value. Either make it more prominent (`opacity-20`, larger size) or remove it.
- No support for background imagery — this is the single biggest limitation.
- Padding `py-14 sm:py-18 lg:py-20` (56/72/80px) is too compact. Reference inner-page heroes use 100-140px.
- **Fix:** Extend to accept optional `backgroundImage?: string` and `backgroundAlt?: string` props. When provided, render an `<img>` with gradient overlay.

### Data Display Components

#### WeatherWidget (`src/components/weather-widget.tsx`)

The most problematic component on the site. See C3 above for full analysis. Summary of specific code issues:

- **Line 276:** `text-[10px]` — below minimum readable size. Change to `text-xs` (12px).
- **Line 262:** `bg-gray-50/60 border border-gray-100` — forecast cards are near-invisible. Need more visual presence.
- **Lines 196-234:** TodayCard crams 4 data points (sky, temp, wind, UV) into a single flex row with mixed `text-sm`/`text-xs` sizing. No visual hierarchy.
- **Line 405:** Widget heading "Tiempo" is generic. Consider "Prevision meteorologica" or "El tiempo hoy."
- **Lines 243-252:** `WindDirDegrees` map for rotating arrow icons is a nice touch but the arrows at `h-3 w-3` (line 278) are too small to read directionally.

#### BeachStatusWidget (`src/components/beach-status-widget.tsx`)

- Better styled than the weather widget — uses `bg-ocean-50/40` tint and `border-ocean-100`.
- The `FlagCircle` (lines 57-71) is a `h-4 w-4` colored dot — functional but could be more prominent. Consider `h-5 w-5` or using an actual flag icon.
- Off-season message (lines 157-174) is well-handled.
- The `max-h-0 overflow-hidden opacity-0` trick for not-found state (lines 147-152) is clever for avoiding layout shift.

#### PracticalInfoCard (`src/components/practical-info-card.tsx`)

- The `InfoRow` component (lines 87-98) creates a monotonous list of `dt/dd` pairs separated by `border-b border-gray-100`. With 10 potential rows, this becomes a data table.
- Badge-styled values (occupancy, access, water quality, child-safe, shade) at lines 146-204 use `rounded-full px-2.5 py-0.5 text-xs` — these are the most visually interesting elements but they are tiny and buried in the row layout.
- **Key issue:** All information is presented with equal visual weight. Length (a number) looks the same as water quality (a colored badge) looks the same as best season (a text string). There is no hierarchy.
- **Fix:** Extract the top 3-4 most useful facts (water quality, occupancy, access, length) into a visual summary grid at the top. Show remaining details in a collapsible section below.

#### ServicesGrid and ActivitiesGrid

- Both components are structurally identical (same grid, same card styling, same icon treatment). See I6 above.
- The `rounded-xl border border-gray-200/60 bg-white px-3.5 py-3 shadow-sm` styling creates cards-within-cards (since these grids are already inside a card container on the beach detail page). This nesting creates visual confusion.
- **Fix:** Remove the per-item border/shadow when the grid is inside a parent card. Use a simpler pill or tag style instead.

#### ContactInfo (`src/components/contact-info.tsx`)

- Clean implementation with consistent icon + link pattern.
- The icons at `h-4 w-4` are small. Consider `h-5 w-5`.
- This component works well in the sidebar but could be integrated closer to the map section.
